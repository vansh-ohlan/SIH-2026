# AI/ML Dataset

This directory contains data assets for the AI/ML pipeline: raw scanned
documents, preprocessed images, and manually verified ground truth.

## Directory Layout

```
data/
├── raw/
│   └── ror/          # Original scanned documents (images/PDFs)
├── processed/        # Preprocessed images ready for OCR
├── ground_truth/     # Manually verified structured data and metadata
├── jamabandi_analysis.md
└── README.md
```

## Raw vs Processed vs Ground Truth

- **raw/ror/** — Original files as obtained. Never modify these files.
- **processed/** — Output of the preprocessing pipeline (grayscale, denoised,
  deskewed). Derived from `raw/ror/`.
- **ground_truth/** — Manually verified structured data and per-sample
  metadata. This is the source of truth for evaluation.

## Naming Convention

Use lowercase, hyphen-separated identifiers:

```
{state}-{district}-{tehsil}-{village}-{document_type}-{serial}.{ext}
```

Example: `rj-jaipur-jaipur-amer-khata-001.pdf`

Ground-truth metadata files use the same basename with `.json`:

```
rj-jaipur-jaipur-amer-khata-001.json
```

## Ground-Truth Verification

Ground truth must be created by a human reviewer using the original document.
Record every field value exactly as it appears on the document, including
spelling and formatting. Mark uncertain fields with `null` and add a note.

## Data Privacy

- Do not commit real personally identifiable information (PII) to this
  repository.
- Use synthetic data for development whenever possible.
- If real documents are used, ensure they are legally obtained public samples
  and strip or redact sensitive personal details before committing.
- Add any sensitive sample paths to `.gitignore`.

## Synthetic Data

Synthetic samples are generated by `ai_ml/synthetic/generator.py` and stored
separately from real samples. Synthetic samples must be clearly labeled in
their metadata with `"source": "synthetic"`.

## Security Rules

- Never commit government IDs, full names, addresses, or financial details in
  plain text.
- Review all changes to `data/` before pushing.
- When in doubt, use synthetic data.

## Rajasthan Jamabandi Reference

For a detailed analysis of the Rajasthan Jamabandi / Record of Rights document
structure, fields, layout, OCR challenges, and pipeline recommendations, see
`jamabandi_analysis.md`. That document is based on publicly available
references and is intended for planning purposes only; it must be validated
against actual physical documents before the extraction pipeline is finalized.
